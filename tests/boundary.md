# Agent 边界测试题集

> 目的：系统化摸清「模型能力上限」与「脚手架兑现率」各自的边界。
> 方法：分层归因法（框架层 / 工具层 / 模型层），方法论详见 [NOTES.md](../NOTES.md)「调试实录」。

## 使用说明

### 评分标准

| 标记 | 含义 |
|---|---|
| PASS | 一次完成，无人工干预 |
| PARTIAL | 靠错误回喂自愈后完成，或部分完成 |
| FAIL | 放弃、死循环、语言漂移到不可用 |
| FABRICATE | 编造结果（声称做了实际没做的事）——最危险，必须单独标记 |

### 归因速查

翻车后按顺序排查，把锅分到正确的层：

1. **只换模型、其余不动**，重跑同一题 → 表现变了 = 模型层
2. 看终端「调用工具」面板 + `/history` → tool_calls 通道是否正确 = 框架层
3. `python -m my_agent --check` → 工具本身行为 = 工具层
4. 以上都定位不了 → 把 tee 日志交给 AI 助手分析

### 跑法

```powershell
python -m my_agent | Tee-Object agent-session.log   # 全程留痕，便于事后分析
```

每题一轮对话，结果填入各表；跨题有依赖时按编号顺序跑。

## 一、阶梯任务（测可靠规划步数）

目标：找到当前模型「从哪一级开始崩」。**「可靠步数」是比「聪明与否」更有用的量化指标。**

| 编号 | 任务 | 考察点 | 预期行为 |
|---|---|---|---|
| L1-1 | 帮我计算 (123*456)/7 | 单工具单步 | 调 calculate，答案 8012.57 |
| L1-2 | 当前目录下有哪些文件？ | 单工具单步 | 调 list_dir，如实转述 |
| L1-3 | 读 README.md，这个项目是干什么的？ | 单工具+阅读理解 | 调 read_file，正确概括 |
| L2-1 | 把「Agent 边界测试」写入 tests/tmp-write.txt | 单步写文件 | 调 write_file |
| L2-2 | 用 shell 查一下当前 python 版本 | 平台感知 + shell | run_shell 执行版本查询 |
| L3-1 | 算出 888*111，写入 tests/tmp-result.txt，再读出来验证 | 两步串联+自验证 | calculate → write_file → read_file，三步全对 |
| L3-2 | 读 requirements.txt，这个项目有几个依赖？ | 读+计数 | 3 个（httpx / rich / python-dotenv） |
| L4-1 | my_agent 目录下所有 .py 文件一共多少行代码？ | 多文件遍历+累加 | list_dir → 多次 read_file → 求和（用 shell 也算合理路径） |
| L4-2 | 在 tests/tmp/ 下创建 note.txt 写一句话，再确认它存在 | 创建+验证 | write_file → list_dir 或 run_shell |
| L5-1 | 读一下 tests/不存在的文件.txt | 错误处理 | 工具返回 ERROR → 如实告知不存在，**不编造内容** |
| L5-2 | 用 ls -la 列出当前目录的文件 | 平台陷阱（Windows/cmd） | 报错后自愈改用 dir，或向用户说明差异 |

## 三、历史压力（测上下文边界）

## 基线档案（2026-10-14，llama3.2:3b，v0.1.3）

- **L1 级稳定通过**：999*999、888*111、(123*456)/7、list_dir 均一次正确
- **多工具任务曾翻车**：幻觉参数 `expression_type`、工具调用泄漏成正文 → v0.1.2「文本调用回收」修复
- **语言漂移**（中英韩夹杂）→ v0.1.3 `temperature=0.4` 修复
- **拒答「你好」**→ 脚手架修复（英文系统提示+显式规则）。同一模型行为剧变，是「框架层决定兑现率」的直接证据
